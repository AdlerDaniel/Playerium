# Loudness and appearance — 1.7.8

Windows and Android measure the whole recording using FFmpeg loudnorm (integrated LUFS and true peak). Target loudness is -18 LUFS, limited to -1 dBTP and at most +18 dB boost / -30 dB attenuation. This keeps original dynamics and avoids amplifying silence. Some highly dynamic recordings cannot reach the target without exceeding the peak limit, so equality is approximate. Files are not rewritten. Measurements are cached against file identity, size and modification time; the next queue entry is analyzed in advance. The first playback of an unmeasured recording can take longer. Analysis failures preserve playback with unity gain.

Windows applies gain before the existing equalizer and user volume; a final compressor protects against EQ-induced overload. Android applies gain in the ExoPlayer PCM audio processor owned by the media service, so normalization survives Activity closure and notification playback. The processor keeps stereo channel gain identical, ramps gain updates and clamps exceptional overshoots. Android 5/6 retain playback; bundled FFmpeg analysis requires Android 7+. Local browser blobs up to 64 MiB use gated K-weighted measurement with a conservative sample-peak margin; larger browser files retain playback without analysis to avoid excessive memory use.

Verified locally: real FFmpeg measurements of two tone WAVs with a 12:1 amplitude difference converge to within 3 dB; cached measurements repeat and source bytes remain intact. Unit coverage includes loudness/peak limits and silence gating. Browser integration checks the actual gain graph, user volume independence, paused seeking and shuffle without source reload. Android instrumentation covers real native measurement and PCM processing; it runs in release automation on API 29 and API 35 with 16 KB pages.

Floating hints use one viewport-level tooltip with keyboard focus support, placement flip, edge clamping and dismissal on scroll/click/Escape/blur. Menus remeasure when their contents or viewport change, constrain height and scroll long lists internally; closing removes resize listeners. Forms keep action buttons reachable and long tokens wrap. Browser coverage exercises top/right edges, a 360/320px-high desktop window, 25 long playlist names, credits, form actions and resize.

Six persistent palettes recolor the existing surface tokens, backgrounds, player/navigation, cards, menus, gradients and selections. Light brown uses a light color scheme. Browser checks on desktop and phone cover all six themes, distinct surface colors, persistence, no horizontal overflow, and at least 4.5:1 contrast for primary/secondary text and accent button labels. Screenshots were visually reviewed.

Primary implementation references: [FFmpeg loudnorm](https://www.ffmpeg.org/ffmpeg-filters.html#loudnorm), [Media3 1.3.1 audio sink factory](https://github.com/androidx/media/blob/1.3.1/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/DefaultRenderersFactory.java).
