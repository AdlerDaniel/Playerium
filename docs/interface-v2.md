# Interface v2 — agreed scope

Implement proposal items 1, 2, 6–14, 16–20 for Windows and Android. Items 3, 4, 5 and 15 are excluded: no new home pins, home recommendations, listening-history screen or search/library filters.

1. Semantic contrasting surfaces and controls in all six palettes.
2. Restrained cover-derived ambient tint with stable artwork and safe fallback.
6. Separate Windows mini-player window controlling the existing audio session.
7. Interruptible cover transition between compact and full player, with reduced motion.
8. Reachable Android controls and next-track action in the compact player.
9. Hold/vertical-offset fine seeking with preview and one commit on release.
10. Manual versus collection queue sections, reorder and explicit group clearing.
11. Persistent visible output-device label in every player.
12. Resizable persistent task sidebar; use existing Now Playing/Queue tasks, omit History (item 5 excluded).
13. Keyboard/touch search suggestions from the library and existing query history.
14. Stable best-match and grouped search results with retained focus.
16. Artist sections: popular, all songs, collaborations and saved tracks.
17. Desktop playlist composer with search and drag/drop ordering.
18. Multi-playlist save sheet with membership indicators, search and inline creation.
19. Multi-track selection with desktop modifiers and Android long press, batch actions and undo.
20. Inline loading/download/availability states and retry with no source-provider clutter.

Preserve existing home content, native playback, normalization, favorites, playlist IDs and synchronization. Reuse current ES modules, menus, artwork and theme tokens. Keep the approved Cyrillic headphone icon. Concept mockups are visual references, not official track covers or catalog metadata.

Validation: source and model checks, browser interactions at phone/desktop widths, keyboard/reduced motion, actual Electron two-window playback, Android build/lint/runtime, then signed release verification if publishing.
