# Playerium

Локальный музыкальный плеер для Windows, Android и браузера: плейлисты, избранное, поиск, обложки, эквалайзер.

## Запуск и проверка

Нужен Node.js 22 или новее.

```sh
npm ci
npm start
npm run check
npm test
npm run test:desktop
npx playwright install chromium
npm run test:browser
```

Проверка Electron требует графического окружения (в Linux — X11/Xvfb); в CI она выполняется на Windows и проверяет реальный сигнал Web Audio, а не только состояние воспроизведения.

Для браузера запустите `python3 -m http.server 8080` и откройте `http://localhost:8080`. Для браузерных тестов также нужен Python 3. В Linux можно указать установленный Chromium через `PLAYERIUM_BROWSER_PATH`.

## Музыкальная библиотека

- Windows: выбранные пользователем папки сканируются асинхронно; теги MP3, FLAC, WAV, OGG, M4A и AAC читает `music-metadata`. Аудио воспроизводится по потоковому протоколу без копирования целых файлов в JavaScript.
- Android: папки выбираются через Storage Access Framework, метаданные извлекаются системным парсером. Фоновым воспроизведением, очередью, уведомлением, аудиофокусом и отключением наушников управляет Media3/ExoPlayer. Нативный эквалайзер сопоставляет десять регуляторов с доступными аппаратными полосами; поддержка эффектов зависит от устройства.
- Браузер: файлы либо дескрипторы доступа сохраняются в IndexedDB. Поддержка кодеков зависит от браузера. Встроенный веб-парсер читает ID3/FLAC; метаданные других форматов могут использовать имя файла. Если разрешение на папку истекло, выберите её заново. Отдельно выбранные файлы сохраняются в хранилище браузера и занимают место на диске.
- LRC-файлы связываются с аудио по имени и каталогу. Обложки хранятся как данные изображения, а временные ссылки создаются заново при запуске.
- Повторное сканирование сохраняет ID, лайки и ссылки из ручных плейлистов. Исчезнувший файл помечается недоступным и удаляется из автоматического плейлиста папки.
- Большие таблицы показывают только видимые строки. `Enter` или пробел на строке запускает трек.
- Импортированная музыка собрана в «Добавленные». В общем списке медиатеки показываются эта коллекция, любимые треки и созданные пользователем плейлисты. Группировка по исполнителям и альбомам доступна через соответствующие фильтры.
- Нажатие на любую область строки, включая название, исполнителя и альбом, воспроизводит трек. Отдельные кнопки сохранения и меню выполняют свои действия. Кнопки запуска коллекций переключаются в паузу и продолжают текущий трек без сброса позиции.
- Полосы прокрутки скрыты; прокрутка касанием, колесом и клавиатурой сохранена. Перемотка поддерживает перетаскивание и стрелки клавиатуры, а обновления времени не сбивают выбранную позицию во время перетаскивания.

Переход Android с прежнего `file://`-адреса на защищённые ресурсы приложения включает перенос медиатеки и настроек. Данные старой IndexedDB не удаляются. Добавленные через старую браузерную сессию аудиофайлы, которые никогда не сохранялись на диск, потребуется выбрать повторно.

## Сборки

Windows:

```sh
python -m pip install pillow==11.1.0
python scripts/generate_icons.py
python scripts/prepare_music_runtime.py --windows
npm run build:win
```

Android: JDK 17, Android SDK 34 и Gradle 8.4.

```sh
npm run android:assets
python scripts/generate_icons.py
python scripts/prepare_music_runtime.py --android
gradle -p android assembleDebug lintDebug
```

Debug APK предназначен для разработки и подписан стандартным debug-ключом. Его нельзя устанавливать поверх публичного release APK. Для проверки обновления существующей установки собирайте release с прежним ключом подписи.

## Подпись Android

Существующий ключ сохраняется без замены. Ключей и паролей в текущих исходниках быть не должно. Для GitHub Actions настройте Secrets:

- `PLAYERIUM_KEYSTORE_BASE64`
- `PLAYERIUM_STORE_PASSWORD`
- `PLAYERIUM_KEY_PASSWORD`
- `PLAYERIUM_KEY_ALIAS`

С учётной записью GitHub, имеющей право управлять Actions Secrets, выполните из клонированного репозитория:

```sh
python scripts/migrate-signing-secrets.py
```

Скрипт загружает **оригинальный** ключ и его параметры из зафиксированного исходного коммита напрямую в Secrets, не печатая значения. Новый ключ не генерируется. Если исходный коммит отсутствует в shallow clone, сначала выполните `git fetch --unshallow`. Удаление из текущих файлов не изменяет историю Git.

Для локальной release-сборки задайте `PLAYERIUM_KEYSTORE_PATH` (абсолютный путь), `PLAYERIUM_STORE_PASSWORD`, `PLAYERIUM_KEY_PASSWORD` и `PLAYERIUM_KEY_ALIAS` в окружении. Затем выполните `gradle -p android assembleRelease`. Без существующего ключа и всех параметров release-сборка завершается ошибкой.

## Выпуск версии

1. Обновите `version` в `package.json` и увеличьте `versionCode` в `android/app/build.gradle`.
2. Выполните `npm run version:sync`, затем `npm install --package-lock-only`, проверки и платформенные сборки.
3. Создайте соответствующий тег, например `v1.1.0`.

PR и push в основную ветку запускают проверки, сборку Windows и debug Android с lint. Только тег запускает подписанную release-сборку Android и создаёт черновик GitHub Release с EXE, APK и SHA-256. Ошибка release-сборки не подменяется debug APK. После проверки на устройствах опубликуйте черновик; встроенная проверка обновлений увидит опубликованный релиз.

## Структура

- `js/library.js`: IndexedDB, импорт и синхронизация папок.
- `js/audio-player.js`: воспроизведение, очередь и платформенный адаптер.
- `js/library-views.js`, `js/settings-view.js`, `js/queue-view.js`, `js/mobile-controls.js`: представления медиатеки, настройки, очередь и мобильное управление.
- `js/track-table.js`, `js/virtual-list.js`: таблица и виртуализация.
- `js/update-controller.js`, `js/updater.js`: интерфейс загрузки и проверка релизов.
- `main.js`, `desktop-files.js`, `preload.js`: ограниченный Electron IPC и потоковый доступ.
- `android/.../MediaNotificationService.java`: независимый нативный плеер.

Проект распространяется по лицензии MIT.

### Поиск и сохранение песен 1.5.0

Поиск с главной страницы объединяет локальную медиатеку и музыкальные каталоги.
Одинаковые записи объединяются; обложка и данные релиза дополняются из доступных
каталогов. Каверы, концерты, клипы и ремиксы исключаются из обычного поиска.
Нажатие на песню сохраняет её перед воспроизведением; кнопка скачивания позволяет
сохранить без запуска. Избранное, очередь и плейлисты работают с сохранённой копией.
В меню песни доступно удаление. Скачанная приложением запись удаляется вместе с
её файлами; импортированная запись удаляется из медиатеки и больше не возвращается
при фоновом сканировании.

На Windows сохранение идёт в последнюю выбранную папку, а без неё — в
`Музыка/Playerium`. Android использует выбранную папку с разрешением записи либо
свой каталог музыки. Аудиофайл содержит доступные теги и обложку; рядом сохраняются
JSON с данными и отдельная обложка. Альбом, год, жанр, ISRC и номер трека сохраняются,
если предоставлены для этой записи. Никакие отсутствующие данные не выдумываются.

Нативный поиск работает в Windows и Android 7+. Обычный браузер сохраняет прежний
локальный поиск. Подключены каталоги Apple Music (US/UA), Deezer, MusicBrainz,
Audius, Bandcamp; аудиозаписи ищутся через YouTube Music, YouTube, SoundCloud,
Bandcamp и Audius. Доступность зависит от записи, региона, соединения и ограничений
сервисов. Это не подключение к каталогу Spotify и не гарантия скачивания любой песни.
DRM, платный доступ и авторизация не обходятся. Неудачное сохранение не подменяет
выбранный оригинал другой песней.

В сборки включены отдельные нативные программы Python/yt-dlp/QuickJS/FFmpeg;
см. [лицензии и исходники](MUSIC-NOTICES.md). Android-проверка в CI запускает эти
программы на эмуляторе и проверяет сохранение и удаление настоящего аудиофайла.

### Обновления 1.4.0

В окне обновления остаются только изменения, «Обновить» и «Игнорировать». Игнорирование скрывает текущий релиз при автоматических проверках; ручная проверка в настройках позволяет вернуться к нему.

Windows скачивает официальный файл и проверяет SHA-256, затем закрывает приложение, выполняет тихую установку и запускает обновлённый Playerium. Переносная версия заменяет свой EXE с резервной копией. Для установки на компьютер с ограничениями может потребоваться системное разрешение Windows.

Android сохраняет загрузку при пересоздании окна, проверяет SHA-256, пакет, версию и прежнюю подпись APK и передаёт обновление в PackageInstaller. На Android 12+ запрашивается обновление самого приложения без дополнительного действия пользователя; если Android требует подтверждение, открывается системное окно. После первого разрешения установки из Playerium процедура продолжается автоматически. На Android 11 и старше требуется системное подтверждение установки.

Для перехода с 1.3.1 и более ранних версий необходимо один раз установить 1.4.0 существующим способом: прежние EXE/APK ещё не содержат новый механизм.

### Исправления 1.3.1

Удалена функция текста песен, включая чтение LRC и тегов с текстом. Перемешивание сохраняет текущий трек, позицию и состояние паузы, в том числе в нативном плеере Android. Повторяющиеся целиком названия очищаются при импорте и при загрузке существующей медиатеки; ID треков, избранное и плейлисты сохраняются. Повторы отдельных слов и разные версии названия (например, Live) не удаляются.

### Интерфейс 1.2.0

Главная показывает быстрый доступ и полки с добавленными треками, альбомами, исполнителями и плейлистами. На ПК поиск и кнопка главной находятся в общей верхней панели; поиск внутри медиатеки фильтрует боковой список. «Все треки» открывается из быстрого доступа, поиска или медиатеки. На телефоне используются фильтры главной, нижняя навигация, мини-плеер и полноэкранный плеер с цветом обложки. Настройки открываются по круглой кнопке профиля на главной.

Структура, цвета, размеры и состояния элементов сверены с публичным веб-плеером Spotify (5 октября 2026). Playerium показывает собственную локальную коллекцию; персонализированные рекомендации и каталог Spotify не подключены. Для автономной типографики включён Inter под SIL Open Font License, текст лицензии находится в `assets/fonts/LICENSE.txt`.
